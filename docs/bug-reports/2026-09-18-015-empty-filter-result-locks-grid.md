# BUG-015 — 필터 결과가 0건이면 그리드 전체가 잠긴 것처럼 동작한다

- **보고**: 사용자 제보 (인앱 브라우저에서 확인)
- **영향 버전**: ~v2.27.0 (오버레이 도입 시점부터 — 전 버전 해당)
- **수정 버전**: v2.27.1
- **심각도**: 높음 — 사용자가 스스로 빠져나올 수 없는 상태(갇힘)

## 증상

컬럼 필터나 퀵 필터로 **존재하지 않는 값**을 검색해 결과가 0건이 되면,
"No rows to show" 오버레이가 뜨면서 **그리드 전체가 비활성처럼 되어 아무 조작도 할 수 없다.**
정렬·필터 메뉴·플로팅 필터·툴바가 전부 반응하지 않아, **필터를 되돌릴 방법이 UI에 남지 않는다.**

## 재현 절차

1. 아무 그리드에서 컬럼 필터 또는 `setQuickFilter()`로 없는 값을 검색한다.
2. 결과가 0건이 되어 "No rows to show" 오버레이가 뜬다.
3. 헤더를 클릭해 정렬하거나 필터 메뉴를 열려고 한다 → **아무 반응이 없다.**

## 원인 분석

`.dg-overlay`는 `_overlayEl = el('div', 'dg-overlay', root)`로 **루트에 붙고**
CSS가 `position: absolute; inset: 0; z-index: 5`를 줬는데 **`pointer-events` 선언이 없었다**(기본 `auto`).
루트에는 타이틀·툴바·헤더·본문이 모두 들어 있으므로, 오버레이 한 장이 **그 전부를 덮고 클릭을 흡수**한다.
`z-index: 5`는 고정 컬럼(3)보다 위라 예외도 없다.

계측 (수정 전, `elementFromPoint`로 실제 페인트 순서 확인):

| 상태 | 헤더 셀 중심에서 잡히는 요소 | 헤더 클릭 시 정렬 |
|---|---|---|
| 필터 없음 (대조군) | `dg-header-cell dg-sortable` | 됨 |
| 결과 0건 (실험군) | **`dg-overlay`** | **안 됨** |

- `overlayPointerEvents: "auto"`, `overlayCoversHeader: true`
- 퀵 필터·컬럼 필터 **양쪽 모두** 동일 (`_viewRows.length === 0`이면 공통으로 오버레이가 뜬다)
- `clearFilters()` 같은 **프로그래매틱 경로는 정상 동작** → 데이터가 아니라 **입력이 막힌 것**

즉 "표시 전용 요소"가 상호작용까지 막고 있었다. 그리드를 진짜 잠그는 책임은
`setEnabled(false)`(`.dg-root.dg-disabled::after`)에 이미 따로 있는데, 오버레이가 그 역할을 겸해 버렸다.

## 수정 내용

1. **`dist/datagrid.css`** — 오버레이는 표시 전용이므로 클릭을 통과시킨다.
   ```css
   .dg-overlay { pointer-events: none; }
   .dg-overlay-panel { pointer-events: auto; }  /* 문구는 드래그 복사 가능하게 */
   ```
2. **`dist/datagrid.js`** — `_positionOverlay()`를 추가해 오버레이를 **본문 영역에만** 올린다
   (`top = this._bodyEl.offsetTop`). 타이틀·툴바·헤더가 반투명 막 아래로 들어가
   컬럼 이름까지 흐려지던 **시각적 "비활성" 인상**도 함께 없앤다.
   높이는 CSS의 `bottom: 0`을 그대로 써서 autoHeight처럼 본문이 짧은 레이아웃에서도 문구 자리가 남는다.

## 검증

- **대조군/실험군 분리** — 수정 전엔 두 상태가 서로 다른 답을 냈고(헤더 vs 오버레이), 수정 후엔 둘 다 헤더가 잡히고 정렬된다.
- **갇힘의 반대를 직접 증명** — 0건 상태에서 필터 메뉴 버튼에 손이 닿아 메뉴가 열리고(`reachedButton: true, opened: true`), 메뉴의 **Clear**를 눌러 **UI만으로 20행 복구**.
- 플로팅 필터 입력도 `elementFromPoint`로 직접 잡힘.
- 로딩 오버레이도 같은 규칙(`pointer-events: none`, 헤더 안 덮음).
- `setEnabled(false)`는 여전히 루트를 가로챈다(`dg-root dg-disabled`) — **역할 분리 유지**.
- 오버레이 기하: `startsAtBody: true`, `coversHeader: false`, `coversTitle: false` — 그룹 헤더 + 플로팅 필터가 겹친 복합 헤더에서도 정확.
- `normal` / `autoHeight` / `fill` 세 레이아웃 모두 문구 패널이 오버레이 안에 완전히 들어가고 **위·아래 가장자리 둘 다** 페인트됨(함정 §24·§28).
- 라이트/다크 모두 확인, 페이지 내 그리드 69개 회귀 없음, 콘솔 에러 0, 단위 테스트 1071 통과.

## 재발 방지

- CLAUDE.md 함정에 추가: **덮는 요소에는 `pointer-events`를 반드시 명시할 것** — "보여주는 것"과 "막는 것"은 다른 책임이고,
  표시 전용이 상호작용을 겸하면 사용자가 그 상태에서 빠져나갈 수단을 잃는다(함정 §9·BUG-006의 오버레이 판, §30의 "해제 경로" 규칙과 같은 계열).
- 검증 규칙: **"빈 상태"를 표시하는 UI는 그 상태를 만든 조건을 되돌릴 수 있는지까지 확인**한다.
  표시가 맞는지만 보면 이 버그는 통과한다.
