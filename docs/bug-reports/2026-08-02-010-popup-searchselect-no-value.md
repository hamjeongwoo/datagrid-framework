# BUG-010: 팝업 폼의 검색형 select가 늘 펼쳐져 있고 고른 값을 표시하지 않음

- **발견일**: 2026-08-02
- **보고자**: 사용자 ("팝업에디터를 열자마자 searchselect가 펼쳐져 있고 아이템 리스트를 클릭 하면 선택은 된거 같은데 실제로 표시는 안나고")
- **심각도**: 높음 — 팝업 폼에서 `editorSearch` 컬럼을 사실상 쓸 수 없음
- **수정 커밋**: 61c50ea

## 증상

`popupEditor` 폼에 `editorSearch` 컬럼이 있으면,

1. 팝업을 열자마자 옵션 목록이 **펼쳐진 채로** 나타나 다른 필드를 아래로 밀어낸다.
2. 목록에서 옵션을 클릭하면 값은 바뀌는데(`popupFieldChanged` 발생) **화면에는 아무 표시가 없다** —
   입력창은 빈 채 `Search…` 플레이스홀더만 남고, 활성 표시(`.dg-active`)도 이전 값에 그대로 있다.

## 재현 절차

1. `http://localhost:8087/examples/features.html#popup-editor-custom`
2. 아무 행이나 더블클릭 → 편집 폼
3. "근무 도시" 필드 확인 → 목록이 이미 펼쳐져 있음
4. 목록에서 다른 도시(예: Tokyo) 클릭 → 상태 줄에는 `City: Seoul → Tokyo`가 찍히지만 입력창은 여전히 빈칸

### 계측 (수정 전)

```
onOpen:  listVisibleOnOpen: true        패널 218px, 필드 241px
         inputValue: ''                 (현재 값이 어디에도 안 보임)
         labelOffsetFromControl: 99px   align-items:center 탓에 라벨이 목록 한복판
onPick:  status: 'City: Seoul → Tokyo'  값은 바뀜
         inputShows: ''                 표시는 없음
         activeOption: 'Seoul'          활성 표시도 안 옮겨감
         listStillOpen: true
```

## 원인 분석

이 위젯은 **인라인 셀 편집 전용 전제**로 만들어졌다: "옵션을 고르면 즉시 커밋하고 **곧 사라진다**".

- 셀에서는 고르는 순간 `finish(true)`로 커밋 → 에디터가 통째로 제거되고 **셀이 값을 다시 그린다.**
  그래서 위젯 자신은 "고른 값을 보여주는 상태"를 가질 필요가 **아예 없었다**.
- 늘 펼쳐져 있는 것도 셀에서는 문제가 아니었다 — 패널 자체가 에디터고, 셀 위에 떠 있다가 사라지므로.

v2.16.0에서 `_createEditorWidget`으로 위젯을 추출해 팝업 폼에 재사용하면서, 이 두 전제가 모두 깨졌다.
팝업에서는 위젯이 저장할 때까지 계속 살아 있으므로 ① 펼쳐진 목록이 폼 레이아웃을 밀어내고
② 표시 상태의 부재가 그대로 드러난다.

## 수정 내용

`hooks.collapsible`를 추가해 **폼에서만 접히는 콤보박스**로 전환한다 (인라인은 종전 그대로):

- 입력창이 현재 값의 label을 보여준다 — 정적 `editorOptions` → lazy 라벨 캐시 → 원시 값 순 폴백(`ssLabelOf`).
- 목록은 **클릭 · 타이핑 · ↓ 에만** 펼친다. `focus`에 걸지 않는 것이 중요하다 —
  팝업이 첫 필드에 주는 **프로그래매틱 포커스만으로 드롭다운이 열리면 안 되기 때문**.
- 고르면 label을 입력창에 남기고 접는다. 블러하면 고르지 않고 친 검색어를 되돌린다.
- 목록이 열린 상태의 `Esc`는 **목록만** 닫고 폼은 유지한다(한 번 더 누르면 폼이 닫힘).
  `Enter`도 선택 + 접기에서 멈추고 저장까지 가지 않는다.
- 펼친 목록은 `position: absolute`라 폼 레이아웃을 밀지 않는다.

`multiselect`/`radio`는 펼친 채로 현재 상태(체크·선택)를 그대로 보여주므로 접지 않되,
세로로 길어 라벨이 목록 한복판에 뜨던 것만 `dg-popup-field-tall`(`align-items: start`)로 고쳤다.

## 검증

- 열자마자: 접힘 · 목록 `display: none` · 입력창에 `Seoul` · 필드 높이 **241px → 60px** · 라벨 오프셋 99px → 8px
- 클릭 → 펼침(7개 옵션, 현재 값 활성) · 펼쳐도 필드 높이 불변(absolute)
- 선택 → 입력창 `Tokyo` + 접힘 → 저장 → 셀 `Tokyo`
- 타이핑 필터(`to` → Stockholm/Tokyo) · ↓+Enter 선택 후 폼 유지 · Esc 2단계 · 블러 시 검색어 복원
- `{label, value}` 옵션은 label 표시, lazy 값은 캐시 없으면 원시 값 폴백, 다크 테마 목록 배경 정상
- **인라인 회귀**: `collapsible` 미전달 → `position: absolute` · 목록 상시 표시 · 고르면 즉시 커밋+닫힘,
  lazy fetch 왕복과 라벨 캐시까지 종전과 동일. 750 passed, 콘솔 에러 0.

## 재발 방지

- **위젯을 다른 컨테이너로 재사용할 때는 그 위젯이 원래 부모의 어떤 성질에 기대고 있었는지 따질 것.**
  여기서는 "곧 사라진다"와 "부모가 값을 다시 그려준다"였다. 특히 **눈에 보이는 상태를 부모에게
  위임하던 위젯**은 그 부모가 없어지면 조용히 상태를 잃는다(에러도, 경고도 없다).
- 폼처럼 위젯이 오래 사는 컨테이너에서는 **"현재 값이 화면에 보이는가"를 명시적으로 단언**할 것 —
  값(`getValue()`)만 확인하면 이 버그를 통과시킨다.
- 프로그래매틱 포커스로 열리는 드롭다운은 버그다. 열기는 **사용자 입력 이벤트**에만 걸 것.
